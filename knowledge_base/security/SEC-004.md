## Purpose

Defines the logging and detection baseline: multi-region CloudTrail with
log file validation, GuardDuty threat detection, S3 server access logging
on data buckets, and AWS Config recording. This SOP also governs Meridian's
security-services trial lifecycle — GuardDuty and Config run during the
initial AWS security-services trial period and are replaced by Prowler-based
coverage plus IAM Access Analyzer afterward (see the README's Security trial lifecycle section).

## Scope

Applies to every account's logging and detection configuration, and to
every GuardDuty finding generated during the trial period (or via
`make seed-guardduty` fixtures). Findings under SEC-004-4.2 and SEC-004-4.4
are account-level, not per-resource.

## Roles & Responsibilities (RACI)

| Activity | Platform/DevOps Engineer | Cloud Security Lead | Engineering Manager |
|---|---|---|---|
| Maintain CloudTrail configuration | R | A | I |
| Triage GuardDuty High findings | C | A/R | I |
| Maintain S3 access logging | R | C | I |
| Manage the security-trial switchover | R | A | C |

## Definitions

- **Trial period**: the ~30 days after first deploy during which Security
  Hub, GuardDuty, and AWS Config run at no incremental cost under AWS's
  included trial allowances.
- **Log file validation**: CloudTrail's digest-file mechanism that lets a
  reviewer cryptographically confirm no log file has been tampered with or
  deleted after delivery.

## Policy Clauses

### SEC-004-4.1 — Multi-region CloudTrail with log file validation

```clause-meta
controls: [CloudTrail.1, CloudTrail.4]
prowler_checks: [cloudtrail_multi_region_enabled, cloudtrail_log_file_validation_enabled]
severity: high
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T2, prod: T2}
references: [DRIFT-004-4.3]
```

Every account MUST have at least one multi-region CloudTrail trail with log
file validation enabled, delivering to a dedicated, access-logged S3
prefix. This trail is the evidentiary backbone for DRIFT-004-4.3's
attribution requirement — without it, "who made this change" cannot be
answered for any finding in this system.

### SEC-004-4.2 — GuardDuty enabled and High findings triaged

```clause-meta
controls: [GuardDuty.1]
prowler_checks: [guardduty_is_enabled]
severity: high
default_action: notify_owner
iac_managed_action: null
risk_tier: {non_prod: T0, prod: T0}
references: [SHARED-001-1.2, SEC-005-5.4]
```

During the trial period, GuardDuty MUST be enabled with the base
protection plan, and every High-severity GuardDuty finding MUST be
triaged within the High SLA (SHARED-001-1.2). This clause is `notify_owner`
/ T0 — the agent's job here is to make sure a human sees the finding
promptly, not to act on it; specific threat types have their own response
procedure under SEC-005-5.4. After the trial switchover, GuardDuty
detection is replaced by weekly Prowler + IAM Access Analyzer + CloudTrail
coverage, with a SHARED-003 exception on file for this clause (see
the README's Security trial lifecycle section).

### SEC-004-4.3 — Server access logging on data buckets

```clause-meta
controls: [S3.9]
prowler_checks: [s3_bucket_server_access_logging_enabled]
severity: low
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T1}
references: [SEC-003-3.1]
```

Every data bucket (SEC-003 Definitions) MUST have S3 server access logging
enabled, delivering to the dedicated access-logs bucket. This is
independent of CloudTrail data events, which Meridian does not enable
account-wide for cost reasons — server access logs are the primary
per-object access record for data buckets.

### SEC-004-4.4 — AWS Config recorder enabled

```clause-meta
controls: [Config.1]
prowler_checks: [config_recorder_all_regions_enabled]
severity: medium
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T2, prod: T2}
references: [DRIFT-001-1.1]
```

During the trial period, AWS Config MUST have an active recorder covering
at least the resource types listed in `infra/modules/security_trial`. After
the trial switchover, the recorder is intentionally disabled to stay within
avoid ongoing cost (Config has no ongoing free allowance), and a pre-seeded
SHARED-003 exception for this clause — compensating control "weekly Prowler
scan + Access Analyzer + CloudTrail" — covers the account itself for the
duration documented in the README's Security trial lifecycle section.

## Procedures

1. Verify CloudTrail: `aws cloudtrail get-trail-status --name <trail>` and
   `aws cloudtrail get-trail --name <trail> --query
   "Trail.{MultiRegion:IsMultiRegionTrail,Validation:LogFileValidationEnabled}"`.
2. Verify GuardDuty: `aws guardduty list-detectors` then `aws guardduty
   get-detector --detector-id <id>`.
3. Triage a GuardDuty finding: `aws guardduty get-findings
   --detector-id <id> --finding-ids <id>` — cross-reference the involved
   resource's tags to determine environment and owner before escalating.
4. Verify Config: `aws configservice describe-configuration-recorder-status`.

## Exceptions

SEC-004-4.2 (post-trial) and SEC-004-4.4 (post-trial) are the two clauses
this system pre-seeds a SHARED-003 exception for at switchover time — see
the README's Security trial lifecycle section for the exact `cloudops exceptions add` commands
run as part of `make trials-off`.
