## Purpose

SHARED-003 defines exceptions generically, across all three domains. This
SOP narrows that mechanism specifically for security findings: which
security findings are eligible for an exception at all, what a
High/Critical exception's compensating control must actually demonstrate,
and the additional CISO approval requirement for Critical security
exceptions given their outsized blast radius.

## Scope

Applies to every security-domain finding (`domain: security`) considered
for a SHARED-003 exception. Cost and drift exceptions follow SHARED-003
directly without this SOP's additional constraints.

## Roles & Responsibilities (RACI)

| Activity | Requesting Engineer | Cloud Security Lead | CISO |
|---|---|---|---|
| Request security exception | R | C | I |
| Approve Medium/Low security exception | I | A/R | I |
| Approve High security exception | I | R | I (must be able to veto) |
| Approve Critical security exception | I | C | A/R |

## Definitions

- **Eligible finding**: a security finding that is not on the ineligible
  list in SEC-006-6.1.
- **Compensating control**: see SHARED-003 Definitions; for security
  findings specifically, a compensating control must reduce *likelihood* or
  *blast radius* of exploitation, not merely document awareness of the
  issue.

## Policy Clauses

### SEC-006-6.1 — Exception eligibility

```clause-meta

prowler_checks: []
severity: null
default_action: null
iac_managed_action: null
risk_tier: {}
references: [SHARED-002-2.5]
```

A security finding is eligible for a SHARED-003 exception unless it falls
under one of the automation-boundary categories in SHARED-002-2.5 (IAM,
KMS, Organizations) **and** represents an active, confirmed compromise
indicator rather than a configuration gap — an active GuardDuty threat
finding (SEC-005-5.4) is never exception-eligible; it is either resolved or
escalated, never suppressed. A configuration gap (e.g. SEC-001-1.1's
wildcard policy) remains exception-eligible even though its remediation is
human-only, since the exception governs the SLA clock, not the remediation
path.

### SEC-006-6.2 — Compensating controls for High/Critical exceptions

```clause-meta
controls: []
prowler_checks: []
severity: null
default_action: null
iac_managed_action: null
risk_tier: {}
references: [SHARED-003-3.1]
```

A compensating control attached to a High or Critical security exception
MUST describe a specific, verifiable mitigation already in place — e.g. "the
resource is not internet-reachable because it sits in a private subnet with
no route to an internet gateway, confirmed via `aws ec2
describe-route-tables`" — not a general statement of intent like "we will
monitor this closely." The Cloud Security Lead MUST reject a request whose
compensating control cannot be independently verified using the procedures
in the finding's originating SOP.

### SEC-006-6.3 — Critical exceptions require CISO approval

```clause-meta
controls: []
prowler_checks: []
severity: null
default_action: null
iac_managed_action: null
risk_tier: {}
references: [SHARED-003-3.2]
```

Any exception for a Critical-severity security finding MUST be approved by
the CISO in addition to the Cloud Security Lead, and MUST NOT exceed 30
days (SHARED-003-3.2's cap for Critical severity — this clause does not
grant a longer duration, only adds an approver). A Critical exception
request without CISO sign-off recorded MUST be treated as not yet granted,
regardless of how urgently it is needed.

## Procedures

1. Before requesting an exception for a High/Critical finding, gather the
   verification evidence described in SEC-006-6.2 using the originating
   SOP's own procedures section.
2. `cloudops exceptions add` records the requester, but does not itself
   enforce the CISO-approval requirement in SEC-006-6.3 — that approval is
   tracked outside this system (Meridian's ticketing system) and referenced
   in the exception's justification field until it is wired
   up as a hard gate.
3. At exception review (SHARED-003 Procedures step 2), the Cloud Security
   Lead specifically re-verifies High/Critical compensating controls, not
   just Low/Medium ones, given their higher risk of silent control decay.

## Exceptions

This SOP defines exception eligibility; it has no exceptions of its own.
