## Purpose

Defines the network-perimeter controls for every VPC Meridian Retail
Technologies operates: what ingress is permitted from the public internet,
the baseline posture of the default security group, mandatory VPC Flow Logs,
and the conditions under which an instance may hold a public IPv4 address.
This is the SOP most frequently exercised by the demo stack, since an
open-to-the-world admin port is the canonical "obviously wrong" security
finding.

## Scope

Applies to every VPC, security group, and network ACL in every account in
scope. Applies equally to Terraform-managed and unmanaged (ClickOps-created)
network resources — an unmanaged security group is still subject to these
clauses, in addition to being a DRIFT-001 finding in its own right.

## Definitions

- **Admin port**: TCP 22 (SSH) or TCP 3389 (RDP).
- **High-risk port**: a port commonly used by a database or administrative
  service not intended for direct internet exposure — for this SOP's
  purposes: TCP/UDP 3306 (MySQL), 5432 (PostgreSQL), 1433 (SQL Server),
  6379 (Redis), 27017 (MongoDB), 9200 (Elasticsearch/OpenSearch).
- **Approved public tier**: a subnet and security-group combination
  explicitly designated (by the Cloud Security Lead, recorded in the
  network architecture register external to this SOP) to host
  internet-facing endpoints, e.g. a public load balancer subnet.

## Policy Clauses

### SEC-002-2.1 — No unrestricted administrative ingress

```clause-meta
controls: [EC2.13, EC2.14, CIS-5.2, CIS-5.3]
prowler_checks: [ec2_securitygroup_allow_ingress_from_internet_to_tcp_port_22, ec2_securitygroup_allow_ingress_from_internet_to_tcp_port_3389]
severity: high
default_action: "ssm_automation:CloudOps-RevokeSGIngressWorld"
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T2}
references: [SHARED-001-1.3]
```

No security group MUST permit ingress on TCP 22 or TCP 3389 from
`0.0.0.0/0` or `::/0`. Administrative access MUST instead use AWS Systems
Manager Session Manager (see SEC-005-5.3) or a scoped, justified CIDR (e.g.
a corporate VPN egress range) recorded in the security group's description.

### SEC-002-2.2 — Default security group restricts all traffic

```clause-meta
controls: [EC2.2]
prowler_checks: [ec2_securitygroup_default_restrict_traffic]
severity: medium
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T1}
references: []
```

Every VPC's default security group MUST have no ingress or egress rules
beyond AWS's implicit deny — applications MUST use purpose-created security
groups, never the default one. This reduces the chance that a resource
launched without an explicit security group inherits unintended access.

### SEC-002-2.3 — VPC Flow Logs enabled

```clause-meta
controls: [EC2.6]
prowler_checks: [vpc_flow_logs_enabled]
severity: medium
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T1}
references: [DRIFT-004-4.3]
```

Every VPC MUST have Flow Logs enabled, delivered to either CloudWatch Logs
or S3, retained per Meridian's log retention standard. Flow Logs are the
primary evidence source for CloudTrail-adjacent network forensics and for
DRIFT-004-4.3's attribution requirement when a security-group change is
under investigation.

### SEC-002-2.4 — Public IPv4 restricted to the approved public tier

```clause-meta
controls: [EC2.9]
prowler_checks: [ec2_instance_public_ip]
severity: medium
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T2, prod: T2}
references: []
```

No EC2 instance MUST hold a public IPv4 address unless it sits in the
approved public tier. This is T2 (not T1) even in non-production, because
removing a public IP can silently break connectivity for legitimate
use-cases (e.g. a developer's temporary test box reachable by design) — the
change window and second approval exist specifically to catch that before
it happens.

### SEC-002-2.5 — No unrestricted access to high-risk ports

```clause-meta
controls: [EC2.19, EC2.18]
prowler_checks: [ec2_securitygroup_allow_ingress_from_internet_to_high_risk_tcp_ports]
severity: critical
default_action: "ssm_automation:CloudOps-RevokeSGIngressWorld"
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T1}
references: [SHARED-001-1.3]
```

No security group MUST permit ingress on a high-risk port (Definitions,
above) from `0.0.0.0/0` or `::/0`. This is Critical, not High, because these
ports front stateful data stores directly — a successful connection is
frequently sufficient for data exfiltration without any further privilege
escalation.

## Procedures

1. To list all security groups with world-open admin or high-risk ports:
   `aws ec2 describe-security-groups --query
   "SecurityGroups[?IpPermissions[?(FromPort==\`22\` ||
   FromPort==\`3389\`) && contains(IpRanges[].CidrIp, '0.0.0.0/0')]]"`.
2. To verify Flow Log status for a VPC: `aws ec2
   describe-flow-logs --filter Name=resource-id,Values=<vpc-id>`.
3. `CloudOps-RevokeSGIngressWorld` (SEC-002-2.1, SEC-002-2.5's default
   non-IaC action) revokes only the specific offending rule (matching CIDR
   + port), never the entire security group, and logs the exact rule
   removed to the audit trail before executing.

## Exceptions

A temporary business need for broader ingress (e.g. a third-party security
scan requiring direct access) requires a SHARED-003 exception with a
compensating control such as a time-boxed CIDR restriction and a named
requester, never an open-ended `0.0.0.0/0` exception.
