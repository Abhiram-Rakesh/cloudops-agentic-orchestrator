## Purpose

Defines the baseline hardening posture for every EC2 instance Meridian
Retail Technologies runs: IMDSv2 enforcement, SSM management (as the
replacement for SSH key pairs), and the response procedure when GuardDuty
reports an active threat against an instance.

## Scope

Applies to every EC2 instance in every account in scope, including
`t4g.micro` instances in the ephemeral demo stack.

## Roles & Responsibilities (RACI)

| Activity | Application Owner | Platform/DevOps Engineer | Cloud Security Lead |
|---|---|---|---|
| Launch a new instance | R | C | I |
| Enforce IMDSv2 | I | R | A |
| Onboard an instance to SSM | I | R | A |
| Execute GuardDuty EC2 threat response | I | R | A |

## Definitions

- **IMDSv2**: the session-oriented Instance Metadata Service, which
  requires a token for every metadata request and is not vulnerable to the
  SSRF-based credential-theft pattern that IMDSv1 permits.
- **SSM-managed**: an instance with the SSM Agent running and an attached
  instance profile granting `AmazonSSMManagedInstanceCore`, visible in
  `aws ssm describe-instance-information`.
- **Quarantine security group**: a security group with no ingress and no
  egress, used to isolate a compromised instance during investigation
  without terminating it (preserving forensic state).

## Policy Clauses

### SEC-005-5.1 — IMDSv2 required

```clause-meta
controls: [EC2.8]
prowler_checks: [ec2_instance_imdsv2_enabled]
severity: high
default_action: "ssm_automation:CloudOps-EnforceIMDSv2"
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T2}
references: [SHARED-001-1.3]
```

Every EC2 instance MUST have `HttpTokens=required` (IMDSv2 enforced) and
`HttpEndpoint=enabled`. An instance with `HttpTokens=optional` is High —
raised to Critical if the instance is also internet-exposed and holds
credentials via an attached instance profile, since that combination is the
canonical SSRF-to-credential-theft chain.

### SEC-005-5.2 — Instances must be SSM-managed

```clause-meta
controls: [SSM.1]
prowler_checks: [ssm_managed_compliant_patching]
severity: medium
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T1}
references: [SEC-005-5.3]
```

Every EC2 instance MUST be SSM-managed (Definitions, above). This is a
prerequisite for SEC-005-5.3 (no long-lived SSH keys) — an instance cannot
retire its key pair safely until Session Manager access is confirmed
working.

### SEC-005-5.3 — No long-lived SSH key pairs

```clause-meta
controls: []
prowler_checks: [ec2_instance_managed_by_ssm]
severity: low
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T1}
references: [SEC-005-5.2]
```

New instances MUST NOT be launched with an EC2 key pair; administrative
access MUST use Session Manager (SEC-002-2.1). An existing instance with a
key pair attached is Low severity while SEC-005-5.2's SSM prerequisite is
being rolled out, and is expected to be remediated by simply not
propagating the key pair on next replacement, not by an in-place change
that could lock out access before Session Manager is confirmed working.

### SEC-005-5.4 — GuardDuty EC2 threat response

```clause-meta
controls: []
prowler_checks: []
severity: high
default_action: manual_ticket
iac_managed_action: null
risk_tier: {non_prod: T2, prod: T2}
references: [SEC-004-4.2]
```

When GuardDuty reports an active EC2 threat finding (e.g.
`UnauthorizedAccess:EC2/SSHBruteForce`,
`Recon:EC2/PortProbeUnprotectedPort`) against an instance, the response
procedure below MUST be followed. This is `manual_ticket` at T2 — a human
executes the isolation steps, drawing on the agent's drafted procedure —
because network-isolating a running instance is consequential enough that
Meridian requires a human in the loop even during the trial period when
GuardDuty is active.

## Procedures

1. Check IMDSv2 status: `aws ec2 describe-instances --instance-ids <id>
   --query "Reservations[].Instances[].MetadataOptions"`.
2. Check SSM management: `aws ssm describe-instance-information
   --filters Key=InstanceIds,Values=<id>`.
3. **GuardDuty EC2 threat response** (SEC-005-5.4):
   a. Attach the quarantine security group (Definitions) to the instance,
      replacing all other security groups — do not terminate it.
   b. Take an EBS snapshot of every attached volume for forensic
      preservation.
   c. Notify the Cloud Security Lead and open an investigation ticket
      referencing the GuardDuty finding ID.
   d. Do not restore normal network access until the investigation
      concludes the instance is not compromised, or until it is replaced
      entirely by a known-good instance.

## Exceptions

An instance that legitimately requires IMDSv1 for an unmigrated legacy
workload requires a SHARED-003 exception with a documented migration plan
and a compensating control (e.g. the instance is not internet-exposed and
has no attached instance profile beyond read-only CloudWatch metrics).
