## Purpose

Defines Meridian Retail Technologies' baseline for protecting data at rest
and preventing accidental public exposure: account- and bucket-level S3
Block Public Access, mandatory TLS-only bucket policies, EBS encryption,
and S3 versioning for data buckets. Public S3 exposure is one of the most
common real-world breach vectors for retail platforms handling customer
order data, which is why this SOP treats it as High-to-Critical by default.

## Scope

Applies to every S3 bucket and EBS volume in every account in scope,
including buckets holding synthetic/demo data. `demo/infra`'s
`orders-demo-exports-*` bucket is an intentional, contained violation of
this SOP used to exercise these clauses end to end (see
`demo/docs/VIOLATIONS.md`) — it is never used for real customer data.

## Definitions

- **Block Public Access (BPA)**: the four S3 settings
  (`BlockPublicAcls`, `IgnorePublicAcls`, `BlockPublicPolicy`,
  `RestrictPublicBuckets`) that, together, prevent a bucket or object from
  becoming publicly accessible regardless of its own ACL/policy.
- **Data bucket**: any bucket whose `data-classification` tag is
  `internal`, `confidential`, or `restricted` (i.e., not `public`).
- **TLS-only policy**: a bucket policy statement with `Effect: Deny` on
  `*` principal when `aws:SecureTransport` is `false`.

## Policy Clauses

### SEC-003-3.1 — Account-level Block Public Access

```clause-meta
controls: [S3.1]
prowler_checks: [s3_account_level_public_access_blocks]
severity: high
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T2, prod: T2}
references: []
```

Account-level S3 Block Public Access MUST be enabled with all four settings
`true`, in every account, at all times — with the sole documented exception
of the demo account while `enable_public_bucket_violation=true`
(`demo/infra`), which carries a standing SHARED-003 exception referencing
this clause. Re-enabling account-level BPA is T2 because it can break an
intentionally public asset (e.g. a CDN origin) if one exists undocumented;
the second approval exists to catch that.

### SEC-003-3.2 — Bucket-level Block Public Access and public policies

```clause-meta
controls: [S3.8]
prowler_checks: [s3_bucket_level_public_access_block, s3_bucket_public_access, s3_bucket_public_write_acl, s3_bucket_public_read_acl]
severity: high
default_action: "ssm_automation:CloudOps-EnableS3BlockPublicAccess"
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T2}
references: [SHARED-001-1.3]
```

Every S3 bucket MUST have bucket-level Block Public Access enabled, and
MUST NOT carry a bucket policy or ACL granting `Principal: "*"` read or
write access, unless the bucket's `data-classification` tag is `public`
and the public grant is explicitly scoped to a documented prefix (as in the
demo's `public/dummy_orders.csv`, a synthetic fixture). Per
SHARED-001-1.3, a public grant on a `confidential`/`restricted` bucket is
raised to Critical.

### SEC-003-3.3 — EBS encryption at rest

```clause-meta
controls: [EC2.3, EC2.7]
prowler_checks: [ec2_ebs_volume_encryption, ec2_ebs_default_encryption]
severity: medium
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T2, prod: T2}
references: []
```

Every EBS volume MUST be encrypted, and account-level default EBS
encryption MUST be enabled so that new volumes are encrypted automatically.
This is T2 rather than T1 because encrypting an existing unencrypted
volume requires a snapshot-copy-and-swap procedure that briefly detaches
the volume — a change with enough operational weight to warrant a second
approval even outside production.

### SEC-003-3.4 — S3 buckets must deny non-TLS requests

```clause-meta
controls: [S3.5]
prowler_checks: [s3_bucket_secure_transport_policy]
severity: medium
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T1}
references: [SHARED-004-4.1]
```

Every S3 bucket's policy MUST include a statement denying any request where
`aws:SecureTransport` is `false`. A bucket tagged `cloudops:protected=true`
(e.g. `orders-demo-legacy-payments-*`, representing a legacy system frozen
pending decommission) is still reported under this clause, but per
SHARED-004-4.1 routes to `manual_ticket` at T3 rather than T1, regardless
of this clause's own catalog tier.

### SEC-003-3.5 — Data buckets must have versioning enabled

```clause-meta
controls: [S3.14]
prowler_checks: [s3_bucket_object_versioning]
severity: medium
default_action: manual_ticket
iac_managed_action: "terraform_pr:remediate_security"
risk_tier: {non_prod: T1, prod: T1}
references: [DRIFT-003-3.1]
```

Every data bucket (Definitions, above) MUST have versioning enabled. A
data bucket found with versioning **suspended** where it was previously
enabled is additionally a DRIFT-003-3.1 security-weakening drift finding
and routes through the revert path (`terraform_revert_dispatch`), not this
clause's own default action, per DRIFT-003-3.1's decision table.

## Procedures

1. Check account-level BPA: `aws s3control get-public-access-block
   --account-id <id>`.
2. Check a bucket's policy for public grants: `aws s3api
   get-bucket-policy-status --bucket <name>`.
3. Check EBS default encryption: `aws ec2
   get-ebs-encryption-by-default`.
4. Check a bucket policy for a TLS-only deny statement: `aws s3api
   get-bucket-policy --bucket <name> --query "Policy" --output text | jq
   '.Statement[] | select(.Condition.Bool."aws:SecureTransport"=="false")'`.

## Exceptions

The demo account's standing exception for SEC-003-3.1 (account-level BPA
off, while `enable_public_bucket_violation=true`) is the canonical example
of a SHARED-003 exception: scope=clause, compensating control="bucket
remains BPA-on except for the single, tagged, synthetic-data demo bucket;
no `confidential`/`restricted` data is ever stored in the demo account",
owner=platform-team, reviewed at every demo teardown (`make demo-down`).
